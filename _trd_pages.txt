TRD 4 · Semantic layer and pre-filled seller context
The chatbox never queries raw tables. It talks to a semantic layer: a governed model of
business terms, metrics, bilingual vocabulary and the seller's pre-filled profile. This keeps
answers consistent, avoids text-to-SQL, cuts latency and removes a whole class of
injection risk.

How latency is kept down
Page 16 of 33PartProof — PRD, TRD & Implementation Plan
1. Two paths. The live chat path only reads pre-computed state. Vision extraction and
drafting run in a background queue.
2. Rules before models. Eight of nine checkpoints are code or a human; only CP5b calls
an LLM.
3. Model tiering. A fast model routes intents, screens injection, parses short answers and
phrases questions. The main model handles photos and the summary paragraph.
4. Prompt caching. The system prompt, guardrail policy, glossary and seller card form one
fixed, cached prefix.
5. Pre-computed questions. Questions are written at reconciliation time, so the chat
shows them instantly.
6. Incremental recompute. The propagation map re-renders only affected outputs; most
corrections need no LLM call.
7. Optimistic UI. A correction shows at once with an "updating" badge. The approve
button unlocks only after the critic passes.
8. Caching by file hash. Re-uploading the same photo costs nothing.
9. Timeouts and fallbacks. Each LLM call has a timeout and one retry with JSON repair,
then falls back to the template or marks the field Missing.
Where autonomy is and is not allowed. Agents may decide how to extract and how to
word a question. They may never change a status, assert compatibility, or export.
TRD 6 · Prompt-injection defence and guardrails

fooled, it has no tool that can change a status, assert fitment or export.
